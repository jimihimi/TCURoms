Additional primary community sources read online
https://github.com/TomFLV/5eat-tcu-reverse-engineering/blob/main/docs/ROM-DETAILS.md
The author reports that AC91207000_... actually embeds ACD1207000. Thus a
filename character 9 can be a naming error rather than a real ROM-ID character.
This remains the author's binary finding; no downloaded binary was revalidated
in this pass. This project also uses images from jimihimi/TCURoms, so those
entries are not automatically independent confirmation of that repo's labels.

https://github.com/martinl/openpilot/wiki/Subaru-Fingerprinting-v2
An example block labelled 2018 Crosstrek EDM / 2018 Impreza ADM lists transmission
versions E3E5463100 and E4E5063100 (converted here from the five raw bytes).
Both have third character E. The block's ordering suggests respective mapping,
but combined comments are insufficient to assert that individual pairing.
This supports E among reported EDM/ADM cars; these are diagnostic fingerprints,
not downloadable complete ROM images or independent checksum validation.

Results for requested characters
E: independent community-reported diagnostic examples found; EDM/ADM support
   from the fingerprint source, with the qualification above.
B,8,C,5,6,7: no independently attributable 10-hex-character donor ROM plus
   market identified by this targeted search. Local package-database findings
   remain the current evidence for these characters. Older six-character
   SSM identifiers and engine ECU calibration IDs were not mixed into this set.

Conclusion: keep filename, embedded ID, diagnostic ID, poster's donor description,
and package database applicability as separate fields. No universal third-character
market specification was established. No GitHub updates or source ROM edits made.
